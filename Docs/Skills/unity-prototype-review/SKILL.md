# Hearing Notion prototype review

Use the current AGENTS.md, Docs/ETHICS.md and Docs/Test.md. This recurring workflow replaces improvised compile/playback checks used in earlier media and game fixes.

1. Establish the requested change and affected screens. Record Unity version, local media availability and whether the Main scene is already open. Preserve unsaved work; never open a second Editor against a locked project or close another session to run tests.
2. Run Tools/Tests/run_project_checks.ps1 with configured local Unity/Python paths. Record compiler failures separately from expected Inspector warnings and game/media integrity checks.
3. For native tests in the existing Main Editor, use the explicit PrototypeReviewRunner request described in Docs/Test.md. It uses muted playback and no real demographic submission. Confirm completion from LocalEvidence/prototype-review.txt; a request file or passing compile is not test completion. If UI control is needed, use the installed computer-use skill and returned window state.
4. Test the actual failure trigger, including Back during/after media loading, in-field game first-round actions, random noise pause/cleanup, direct soundscape toggles, listening slider/preview-only trim/Accept, startup popup order, midpoint default and unified sound hub, video controls and actual decoded nonblack frames, final game feedback, whole-page gestures with pinned branded header/footer and moving body/navigation and modal background blocking, form Skip/save/delete with synthetic values and reset. Check portrait, landscape and a representative tall phone viewport. Verify stopped Home separately without Play Mode, and check informational-only routes remain honest. For a portable export, validate its own file hashes/preview and actual playback with ExternalRoot empty; distinguish Android-symbol compilation and desktop portable playback from SDK/IL2CPP/APK/device checks. Never infer physical listening safety from muted engine playback.
5. Capture actual rendered app screens into Marketing/Screenshots. Inspect dimensions and images. Exclude real visitor data and do not invent working features. Mark unavailable or unverified captures honestly.
   For the approved rounded Home, inspect both the top and after-scroll view, verify three yellow/one turquoise/two purple visible module icons, gray deferred meter, seven Home cards and footer-only Research/You, purple DHWANI/Flappy and no Waves control, nonblocking icons and English navigation. Check shared font/heading weights, rounded module/popup surfaces and form-field targets; preserve selected colors and consent/input callbacks. Include inactive popup ancestors when checking action labels; all popup actions must be bold and centered. Run validate_english_content.py after text edits; use explicit UTF-8 reads/writes on Windows and inspect rendered separators/dashes, not just compilation. HNAI item/choice text, original media language, proper titles and original study figures are explicit language exceptions; never translate the instrument merely to make an English scan pass.
6. Fix reproducible, reversible project bugs within scope, rerun affected checks, and record root cause, evidence, changed files, outcome and remaining limitations. Stop a correction attempt after repeated equivalent failure and report the blocker; do not bypass permissions or change external/system settings.
7. Update the feature catalog, module guides, dated modification report, continuous history table and skill register as affected. Publish only authorized project-authored Markdown, preserving the remote head and verifying content. Local logs, media, screenshots, executables and private paths are not authorized for publication.

For an authorized Android toolchain upgrade/build, work in a separate portable copy and verify the chosen Editor against Unity's security advisory. Preserve the open desktop project. Validate bundled hashes, then rerun native regression with the new Editor before building. Select Android at batch startup with -buildTarget Android; record the real SDK/NDK/JDK and build outcome. An APK's existence alone does not prove successful compilation, signing, ABI compatibility or playback. Inspect the final build result and APK metadata/signature. Install only when the user has connected and authorized the intended device; phone debugging/RSA prompts remain user actions. Stop on an installation/permission or repeated build blocker and document the actual diagnostic. See Docs/AndroidDeployment.md for the current tested configuration and remaining device checks.

Inputs: current project, relevant failing behavior and optional synthetic test data. Outputs: local test evidence and authentic captures, scoped fixes and a reviewed modification report. Availability: explicit invocation by reading this file under Docs/Skills; automatic discovery is not claimed.

Phone correction regression: inspect all four research stages after switching; verify fixed selector rows and measured figures, left-aligned HNAI responses, hardware Back/modal ordering, inline comparison after context, and native full-screen video return. Wait beyond the former countdown before explicit Flappy Ready, then check audio promptly before an unattended collision. Read process inventory with sufficient permissions before concluding an Editor is absent; never infer process exit from a sandbox-filtered inventory. Keep a timed-out run separate from later passing evidence.

Pinned-chrome follow-up: compare header/footer world positions before and after scrolling, exercise all footer routes and profile dismissal, verify four displayed video topics and song-list-first direct toggles. On Android, test visible Return to page and hardware Back from the native activity, confirming paused inline position restoration. Desktop decoding does not verify this native activity.

For an app-owned Android Activity, verify both its merged APK manifest entry and compiled DEX class before installation. In this Unity Android library setup, use Gradle-standard src/main/java: the generated library config leaves legacy src disabled. Never repair generated Library/Gradle files in place.

Repeated footer/gain/game review: cloned UI can retain footer objects but lose runtime UnityEvent callbacks; exercise all actions from the cloned SoundHub, not only Home. Measure the actual bottom-note/footer gap on short and long pages. Check multimedia/game unity gain independently from the preview-only slider. For moving obstacle pairs, test shared-center collision/render geometry, constant gap size, stationary pairs and freeze/resume; record the completion fixture seed without implying all courses or human usability are validated.

For content-fitted modals, verify both preferred geometry and rendered portrait/landscape width, collapsed empty feedback, the privacy-text/action gap and access to every action. Capture-time viewport changes need the sizing controller on Application Managers ticked explicitly; Canvas-descendant searches will miss it. For inert future-work previews, test Continue-only flow, overview/reentry/reset, visible mockup disclaimers and absence of operational input/media/analysis components. Inspect actual cards after navigation/layout settles, not only event callbacks.

For full-screen future-work previews, verify Canvas bounds, blocking of underlying ScreenViews, visible close/phone Back, modal release on navigation/reset and inert decorative controls. Confirm hub entry/exit separately from internal Continue state. If a run was interrupted by tool/approval availability, retain its incomplete status and record the resumed checks separately.

For supplied raster interfaces, verify source texture/UV regions and preserved aspect ratio rather than procedural resemblance. Check each page owns its in-frame close control and following information retains the requested style and scrolling. Verify visitor action count separately from underlying synthetic save/delete infrastructure.

Video-poster regression: inspect each stable-ID poster before playback, trigger the centered action, verify decoded nonblack frames replace it and Stop/Back/reset restore it. Ensure extraction used actual source content; distinguish AI-enhanced decorative artwork from scientific data and preserve originals. Verify decoration is nonblocking and layout-ignored.

For reference-driven container redesigns, inspect representative option screens after runtime builders/layout settle. A changed border/shadow alone does not verify a requested sheet/card structure. Check surface hierarchy, corner treatment, selection markers and actual pointer/scroll behavior; preserve the approved palette and content.
